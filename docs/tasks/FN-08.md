## What was asked

The delivery plan entry, as you gave it: **"Synthetic data generator"**. Decisions made when it started:

| Question | Decision |
|---|---|
| Scope | Full life-cycle records: scholars with attaches, institutions, yearly progress, payments in XAF, documents and phone changes abroad. Loaded later by each module when its table exists. Nothing new is created in the database now. |
| Awkward cases | A marked share of deliberately awkward cases, each labelled so tests can ask for them. |

## How it works

    npm run seed:data                                    # 200 scholars, default seed, writes synthetic-data.json
    npm run seed:data -- --count 500 --seed 1 --out data/demo.json --force

In code: `generateDataset({ scholars: 300, seed: 9 })` returns `institutions`, `attaches`, `scholars`, `years`,
`documents`, `phones` and `payments`, all linked by identifiers. For 200 scholars with the default seed this is
about 526 academic years, 994 documents, 216 phone numbers and 1997 payments. A test asks for a case with
`scholars.filter((s) => s.edgeCases.includes("late_payment"))`.

The data is placed on 2026-11-05: scholars started between 2021 and 2025, finished ones are `completed`, a few
active ones are `withdrawn` or `suspended` (their payments are `held`). Payments that fall due more than 90 days
after the reference date do not exist yet.

## How to check it

    npm run check

Then `npm run seed:data -- --out /tmp/demo.json` and look at the summary it prints: every label should have a
count above zero. Mutation checks done by hand: removing the `.invalid` rule, the `SYN-` rule or the whole-number
rule from the guard each made a test fail.

## Not included and known gaps

- Nothing is loaded into a database. The modules do that, each for its own tables.
- The amounts, institutions, payment statuses and term dates are assumptions made from what is known of the
  project; they have not been compared with the Ministry's real scales or checked line by line against the
  specification.
- The staging server does not exist yet (FN-03), so the data has not been loaded into staging.
- Documents are records of a status only; there are no files.
- The file is ordinary JSON, so a very large count (the limit is 20 000 scholars) makes a large file.
